## 🎯 设计背景

### 问题

在自动化系统中，AI对用户意图的理解不可能达到100%准确率。如果错误执行，可能造成严重后果：

```
用户说："删除临时文件"
AI理解："删除所有文件"
→ ❌ 灾难性后果
```

### 解决方案

在AI理解后，加入用户确认环节：

```
用户指令 → AI理解 → 确认（如果需要）→ 执行
```

### 确认时机

**需要确认的场景：**

1. **置信度低** (< 70%)
   - AI不太确定用户的意图
   
2. **高风险操作**
   - 删除、清空、格式化、发送邮件等
   
3. **目标模糊**
   - "点击按钮"（没有指定哪个按钮）
   
4. **多个匹配**
   - 找到3个"确定"按钮，不知道点哪个
   
5. **参数缺失**
   - "发送邮件"（缺少收件人）
   
6. **复杂任务**
   - 涉及多步骤的任务

## 💻 实现方案

### 1. 核心类设计

#### IntentConfirmationSystem

**职责：** 管理整个确认流程

```python
class IntentConfirmationSystem:
    """意图确认系统"""
    
    def should_confirm(self, parsed_intent: Dict) -> Tuple[bool, ConfirmationType, ConfirmationPriority]:
        """判断是否需要确认"""
        pass
    
    def create_confirmation_request(self, ...) -> ConfirmationRequest:
        """生成确认请求"""
        pass
    
    def handle_user_response(self, ...) -> Dict:
        """处理用户响应"""
        pass
```

#### ConfirmationRequest

**职责：** 封装确认请求数据

```python
@dataclass
class ConfirmationRequest:
    confirmation_id: str              # 唯一ID
    confirmation_type: ConfirmationType  # 确认类型
    priority: ConfirmationPriority       # 优先级
    message: str                         # 提示消息
    detail: Dict[str, Any]              # 详细信息
    options: List[Dict[str, Any]]       # 选项列表
    allow_skip: bool                    # 是否允许跳过
    timeout: int                        # 超时时间
```

### 2. 确认类型

```python
class ConfirmationType(Enum):
    UNDERSTANDING = "understanding"              # 理解确认
    AMBIGUOUS_TARGET = "ambiguous_target"        # 目标模糊
    MULTIPLE_MATCHES = "multiple_matches"        # 多个匹配
    DANGEROUS_ACTION = "dangerous_action"        # 危险操作
    PARAMETER_MISSING = "parameter_missing"      # 参数缺失
    HIGH_RISK_OPERATION = "high_risk_operation"  # 高风险操作
    COMPLEX_TASK = "complex_task"                # 复杂任务
```

### 3. 优先级

```python
class ConfirmationPriority(Enum):
    LOW = 1       # 可选确认（用户可跳过）
    MEDIUM = 2    # 建议确认
    HIGH = 3      # 必须确认
    CRITICAL = 4  # 强制确认（不可跳过，如删除操作）
```

## 🎯 最佳实践

### 1. 确认策略

**不要过度确认：**

```python
# ❌ 不好：简单操作也确认
"点击确定按钮" → 确认？ → 执行

# ✅ 好：高置信度跳过确认
"点击确定按钮" (confidence: 0.95) → 直接执行
```

**对高风险操作强制确认：**

```python
# ✅ 好：删除操作必须确认
"删除文件" → 确认（CRITICAL，不可跳过）→ 执行
```

### 2. 用户体验

**提供清晰的选项：**

```python
# ❌ 不好：模糊的选项
[1] 是
[2] 否

# ✅ 好：明确的描述
[1] ✅ 理解正确，继续执行
[2] ❌ 理解错误，重新描述
[3] ✏️ 修改理解
```

**允许跳过：**

```python
# 对于低优先级确认，提供跳过选项
[0] 跳过确认（默认执行）
```

### 3. 学习用户偏好

**记录用户选择：**

```python
# 用户总是跳过"点击"操作的确认
→ 学习：点击操作不再确认

# 用户总是选择"确定"而不是"确认"
→ 学习：自动选择"确定"
```

### 4. 超时处理

```python
# 设置合理的超时时间
timeout = {
    "default": 60,      # 默认60秒
    "high_priority": 30, # 高优先级30秒
}

# 超时后默认选择
if timeout:
    return default_choice  # 默认选择第一个选项
```

### 5. 错误处理

```python
# 用户输入无效选择
while True:
    try:
        choice = int(input("请选择: "))
        if is_valid(choice):
            break
        else:
            print("❌ 无效选择，请重试")
    except ValueError:
        print("❌ 请输入数字")
```

## 📝 总结

### 核心价值

1. **可靠性提升 90%** - 通过确认避免错误执行
2. **用户体验改善** - 提供纠错机会
3. **信任度增强** - 用户感到被尊重

### 设计原则

1. **最小打扰** - 只在必要时确认
2. **清晰明确** - 提供易懂的选项
3. **用户控制** - 允许跳过和修改
4. **持续学习** - 适应用户习惯

### 适用场景

- ✅ 高风险操作（删除、发送）
- ✅ 置信度低的理解
- ✅ 多个匹配的目标
- ✅ 复杂的多步骤任务
